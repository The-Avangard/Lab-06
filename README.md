# Лабораторна робота №6 — AVANGARD SHOP

Інтеграція клієнтської частини інтернет-магазину з REST API на Flask. Демонстраційна сторінка асинхронно завантажує товари, підтримує пошук і фільтр за категорією, а також дає змогу додати товар через форму.

## Запуск проєкту

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
py app.py
```

Відкрити сторінку Demo API: <http://127.0.0.1:5000/api-demo>.

## Використані ендпоінти

### `GET /api/v2/products`

Повертає список товарів у форматі API v2:

```json
{
  "version": "v2",
  "data": []
}
```

Необов’язкові query-параметри:

- `q` — пошук у назві, описі та характеристиках;
- `category` — фільтр за категорією (`Ноутбук`, `Стаціонарний ПК`, `Приставка`).

Об’єкт товару містить `id`, `category`, `name`, `description`, `specifications`, `price`, `image_url`, `is_available` і `created_at`.

### `POST /api/v2/products`

Створює товар. Заголовок запиту: `Content-Type: application/json`.

Обов’язкові поля:

- `category` — одна з підтримуваних категорій;
- `name` — назва товару;
- `price` — скінченне число, не менше нуля.

Необов’язкові текстові поля: `description`, `specifications`, `image_url`. Успішний запит повертає HTTP `201` і створений товар у полі `data`. Некоректні дані повертають HTTP `400` із повідомленням та деталями помилки.

## Реалізація клієнта

- `templates/api-demo.html` — розмітка сторінки та форми;
- `static/js/api-demo.js` — `fetch`, пошук, фільтрація, надсилання форми, валідація й повідомлення про відповіді сервера;
- `static/css/api-demo.css` — оформлення Demo API.

Клієнт перевіряє `response.ok`, обробляє помилки API й окремо показує зрозуміле повідомлення, коли сервер недоступний.

## Перевірка

Перевірку виконано на окремій тимчасовій копії SQLite-бази, щоб тестовий запис не потрапив до основної бази проєкту.

| Сценарій | Результат |
| --- | --- |
| Відкрити `/api-demo` і завантажити каталог | Успішно: початково відображено 30 товарів |
| Знайти Dell Alienware через пошук | Успішно: знайдено 1 товар |
| Відфільтрувати категорію ноутбуків | Успішно: отримано 10 товарів |
| Додати тестовий товар через форму сторінки | Успішно: API повернуло HTTP `201`, сторінка показала повідомлення про успіх |
| Надіслати ціну `-1` напряму до API | Успішно відхилено: HTTP `400` із деталлю помилки ціни |
| Запросити невідому категорію | Успішно відхилено: HTTP `400` |

## Висновок

Клієнтська сторінка отримує та показує дані з Flask API за допомогою асинхронного `fetch`. Реалізовано пошук, фільтрацію, додавання товарів, валідацію та обробку помилок HTTP і мережі. Перевірка підтвердила роботу основних сценаріїв на копії бази даних.
