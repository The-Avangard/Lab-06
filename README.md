# AVANGARD SHOP

Навчальний інтернет-магазин техніки на Flask. Проєкт поєднує каталог із кошиком та оформленням замовлень, адміністративну панель і версійований REST API. Сторінка «Демо API» завантажує товари асинхронно через `fetch`.

## Можливості

- каталог ноутбуків, стаціонарних комп’ютерів і приставок;
- пошук товарів та фільтр за категорією;
- кошик, оформлення замовлення і застосування промокоду;
- адміністративне керування товарами, клієнтами, замовленнями, відгуками та промокодами;
- REST API версій `v1` і `v2` для товарів та замовлень;
- сторінка Demo API з асинхронним завантаженням, пошуком, фільтром і формою додавання товару;
- інтерактивна документація API на Swagger UI.

## Технології

- Python 3.9+;
- Flask 3.1;
- SQLite;
- HTML, CSS і JavaScript (`fetch`);
- Flasgger / Swagger UI.

## REST API

Базова адреса локального API: `http://127.0.0.1:5000/api`. Кожен маршрут товарів і замовлень доступний у двох версіях: заміни `{version}` на `v1` або `v2`.

### Товари

| Метод | Маршрут | Дія |
| --- | --- | --- |
| `GET` | `/api/{version}/products` | Список товарів; параметри `q` для пошуку та `category` для фільтра |
| `GET` | `/api/{version}/products/{id}` | Один товар за ID |
| `POST` | `/api/{version}/products` | Створити товар |
| `PUT` | `/api/{version}/products/{id}` | Повністю оновити товар |
| `DELETE` | `/api/{version}/products/{id}` | Видалити товар |

Для створення й повного оновлення потрібні поля `category`, `name` та `price`. Додаткові поля: `description`, `specifications`, `image_url`. Доступні категорії: `Ноутбук`, `Стаціонарний ПК`, `Приставка`.

Об’єкт товару у відповіді містить `id`, `category`, `name`, `description`, `specifications`, `price`, `image_url`, `is_available` і `created_at`.

Приклад створення товару у PowerShell:

```powershell
$body = @{
    category = "Ноутбук"
    name = "Демо ноутбук"
    price = 54999
    description = "Ноутбук для роботи та навчання"
    specifications = "16 ГБ RAM, SSD 1 ТБ"
    image_url = "https://example.com/laptop.jpg"
} | ConvertTo-Json

Invoke-RestMethod `
    -Uri "http://127.0.0.1:5000/api/v2/products" `
    -Method Post `
    -ContentType "application/json" `
    -Body $body
```

### Замовлення

| Метод | Маршрут | Дія |
| --- | --- | --- |
| `GET` | `/api/{version}/orders` | Список замовлень; необов’язковий параметр `status` |
| `GET` | `/api/{version}/orders/{id}` | Замовлення з переліком товарів |
| `POST` | `/api/{version}/orders` | Створити замовлення |
| `PATCH` | `/api/{version}/orders/{id}` | Змінити статус замовлення |

Для створення замовлення передай `customer_name`, `email`, `address` та непорожній масив `items`. Кожен елемент `items` містить `product_id` і `quantity`. Поле `promo_code` необов’язкове. Ціну та суму замовлення сервер обчислює за даними бази.

Одне замовлення може містити до 50 позицій, кількість кожного товару має бути від 1 до 99. Дані відповіді замовлення включають ідентифікатор, контактні дані, адресу, суму, статус, промокод і позиції замовлення.

Приклад тіла запиту:

```json
{
  "customer_name": "Іван Покупець",
  "email": "ivan@example.com",
  "address": "Київ, вул. Хрещатик, 1",
  "items": [
    { "product_id": 1, "quantity": 1 }
  ],
  "promo_code": ""
}
```

Для зміни статусу надішли `PATCH` із JSON-об’єктом `{"status":"В обробці"}`. Допустимі статуси: `Нове`, `В обробці`, `Відправлено`, `Доставлено`, `Скасовано`.

### Формат відповідей

Успішні відповіді `v1` містять дані без обгортки. Версія `v2` повертає їх у полі `data` разом із версією API:

```json
{
  "version": "v2",
  "data": []
}
```

У `v2` помилка має формат `{"version":"v2","error":{"message":"...","details":{}}}`. Для помилок валідації сервер зазвичай повертає HTTP `400`, для відсутнього ресурсу — `404`, а для конфліктів стану — `409`.

У `v1` помилка має формат `{"error":"...","details":{}}`. Наприклад, `409` повертається, якщо товар уже є в замовленні й його не можна видалити, або якщо товар недоступний під час оформлення замовлення.

Повні схеми запитів, параметри та приклади відповідей доступні у [Swagger UI](http://127.0.0.1:5000/apidocs/) після запуску застосунку.

## Налаштування

Застосунок використовує такі змінні середовища:

| Змінна | Призначення | Типове значення |
| --- | --- | --- |
| `DATABASE` | Шлях до SQLite-файлу | `db.sqlite` у корені проєкту |
| `SECRET_KEY` | Підпис сесій Flask | `dev-only-change-me` |

Для локальної роботи типових значень достатньо. Якщо запускаєш застосунок поза навчальним локальним середовищем, задай власний `SECRET_KEY` і не використовуй режим розробки Flask.

## Структура проєкту

```text
app.py                  Створення Flask-застосунку та реєстрація маршрутів
models.py               SQLite-схема, ініціалізація та операції з даними
routes/                 Маршрути магазину, адміністративної панелі та API
templates/              HTML-шаблони Jinja
static/css/             Стилі сайту й Demo API
static/js/               JavaScript-клієнт Demo API
static/images/           Локальні зображення інтерфейсу та категорій
db.sqlite                Локальна база даних
requirements.txt        Залежності Python
lab-reports/             Матеріали й скриншоти звіту
```

Товари для початкового каталогу додаються під час ініціалізації бази. Частина фото товарів завантажується за зовнішніми URL з поля `image_url`, тому для їх показу потрібне інтернет-з’єднання.
