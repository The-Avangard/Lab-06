## Мета роботи

Під’єднати клієнтську частину до REST API, асинхронно отримувати та надсилати дані за допомогою JavaScript `fetch`, а також коректно показувати стан завантаження, успіх і помилки.

## Короткий опис роботи

AVANGARD SHOP — навчальний інтернет-магазин техніки на Flask. Для лабораторної № 6 у ньому створено сторінку `/api-demo`: вона завантажує товари з API, дає змогу знайти їх за назвою або відфільтрувати за категорією та додати новий товар через форму. Після успішного створення список оновлюється асинхронно, а користувач бачить результат.

Сторінка та API обслуговуються одним Flask-застосунком. Запити використовують відносні адреси, тому для цього сценарію CORS не потрібен.

## Реалізація

| Частина | Розташування | Призначення |
| --- | --- | --- |
| Flask-маршрут сторінки | `app.py` | Відкриває `/api-demo` і передає шаблону категорії товарів |
| HTML-шаблон | `templates/api-demo.html` | Розмітка статусу API, пошуку, форми та карток |
| JavaScript-клієнт | `static/js/api-demo.js` | `fetch`, валідація, відображення даних і повідомлень |
| Маршрути товарів | `routes/api_products.py` | Серверні GET і POST операції, перевірка даних і JSON-відповіді |

### Використані запити

| Метод | Endpoint | Призначення |
| --- | --- | --- |
| `GET` | `/api/v2/products` | Отримати список товарів |
| `GET` | `/api/v2/products?q=...` | Шукати товар за назвою |
| `GET` | `/api/v2/products?category=...` | Фільтрувати список за категорією |
| `POST` | `/api/v2/products` | Додати товар у JSON-форматі |

Форма надсилає `category`, `name`, `price`, `description`, `specifications` та `image_url`. Відповідь API версії `v2` містить дані у полі `data`; помилки відображаються з текстом відповіді сервера, якщо він є.

### Обробка станів і помилок

- Під час запиту сторінка показує стан завантаження та блокує повторне натискання кнопок.
- Перевіряється HTTP-статус через `response.ok` і структура відповіді API.
- На клієнті перевіряються категорія, довжина назви, ціна та формат посилання на зображення; дані додатково перевіряє сервер.
- Помилки API та відсутність мережевого з’єднання показуються окремо зрозумілим повідомленням.
- Текст, отриманий із API, додається до DOM через `textContent`; недоступне зображення замінюється заглушкою.
- Після успішного `POST` форма очищується, а список завантажується повторно.

## Контрольні запитання

1. **Що таке асинхронність у JavaScript? Навіщо вона потрібна?**  
   Асинхронність дає змогу почати повільну операцію, наприклад HTTP-запит, і продовжити обробляти інші події сторінки, поки очікується відповідь.

2. **Чим відрізняється GET від POST?**  
   `GET` отримує дані із сервера. `POST` передає дані для створення нового ресурсу.

3. **Що таке JSON і навіщо він потрібен?**  
   JSON — текстовий формат обміну структурованими даними між клієнтом і сервером. Він представляє об’єкти, масиви та їхні поля.

4. **Що робить `fetch()`?**  
   `fetch()` надсилає HTTP-запит і повертає Promise з об’єктом відповіді, з якого можна прочитати статус, заголовки й тіло.

5. **Навіщо використовувати `await` перед `fetch()`?**  
   `await` дає змогу дочекатися результату Promise та послідовно обробити відповідь усередині `async` функції, не блокуючи роботу всієї сторінки.

6. **Що таке CORS і коли він потрібен?**  
   CORS — механізм, який визначає, чи може сторінка звертатися до сервера з іншого origin. У цьому проєкті сторінка й API мають один origin, тому CORS не потрібен.

7. **Як обробляються помилки? Чому недостатньо лише `catch`?**  
   `catch` обробляє мережеві збої та винятки, але `fetch()` не відхиляє Promise лише через HTTP-статус `400` або `500`. Тому код окремо перевіряє `response.ok`, читає повідомлення API та показує його користувачу.
